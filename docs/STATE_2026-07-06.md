## 3. OPS risks (verify outside the repo — cannot be confirmed from code)

- **OPS-1 (P0): cron cadence.** `backend/vercel.json` schedules `/cron/maintenance` at `0 17 * * *` — once per day. `NotificationService.sendMeetupReminders` targets a 30–70-min-out window and its own comment assumes a ~5-min scheduler. On a daily-only cron, meetup reminders, waitlist-expiry promotion, and no-show follow-ups effectively never fire. `LAUNCH_CHECKLIST.md` Phase 1 has this as an unchecked box. **Action: confirm an external scheduler (cron-job.org / GitHub Actions hitting `/cron/maintenance` with `CRON_SECRET`) is live in prod. If not, that's the single highest-impact 30-minute fix available.**
- **OPS-2: avatar upload persistence.** `server.ts` serves `/uploads` from local disk, but Vercel serverless filesystems are ephemeral. `lib/supabaseStorage.ts` exists — confirm avatar writes go to Supabase Storage and the static `/uploads` mount is legacy/dev-only. If any prod path still writes to local disk, uploads silently vanish.
- **OPS-3: rate limiting is per-instance.** Already documented in `server.ts`; `lib/durableRateLimit.ts` exists for the paths that matter. No action unless abuse appears.
- **OPS-4: LAUNCH_CHECKLIST.md is stale.** The app is live but most boxes are unchecked. Either check them off or delete the file — a checklist that can't be trusted is worse than none.

## 4. Security review (new — not covered by AUDIT_2026)

Overall posture is strong: helmet with per-request CSP nonce, strict prod CORS (throws without `CORS_ORIGIN`), layered rate limits keyed by user-then-IP (correct call for campus NAT), JWT with `tokenVersion` revocation + email match + `accountStatus` check on every request, fail-fast `JWT_SECRET`/env validation, timing-safe cron secret comparison, admin gating via `ADMIN_USER_IDS` env, DB-touching health check, graceful shutdown. Findings, minor first-to-worst none critical:

- **SEC-1 (P2): error handler echoes `err.message` to clients** (`server.ts` final handler). Any uncaught Prisma/internal error string reaches the client. Return a generic message for 5xx in production; keep the detailed one in logs.
- **SEC-2 (P3): CSP `imgSrc` allows all of `https:`** — broad but low-risk for an API-mostly server. Tighten to self + Supabase storage domain when convenient.
- **SEC-3 (P3): `optionalAuth` swallows all verification errors by design** — fine, but make sure no privileged read path uses `optionalAuth` expecting a verified user. Worth a one-time grep audit of `optionalAuth` call sites.
- **SEC-4 (info): admin identity is env-var user IDs.** Works at this scale; revisit if admin count grows (move to a DB flag like `isClubReviewer` already does).
